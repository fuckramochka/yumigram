## [ADR-001] Выбор Rust (`grammers`) вместо C++ (TDLib / TMessagesProj)
* **Статус**: ПРИНЯТО
* **Контекст**:
  Предыдущие попытки создания клиента на базе официального форка `Telegram-Android` (`TMessagesProj`) привели к неуправляемому монолиту в 8+ миллионов строк, долгой сборке (20+ минут) и невозможности модификации без регрессий.
* **Решение**:
  Разрабатывать ядро с чистого листа на Rust с использованием модульного движка `grammers` (создатель — Lonami, автор Telethon) + собственные модули локальной БД и перехватчиков приватности.
* **Последствия**:
  * Время инкрементальной сборки сократилось с 20 минут до 1–3 секунд.
  * Безопасность памяти гарантируется компилятором Rust (исключены `SIGSEGV` и `NullPointerException` в нативном коде).
  * Полный контроль над архитектурой ядра без унаследованного спагетти-кода.

## [ADR-002] Выбор Jetpack Compose (MD3) вместо старых XML Views
* **Статус**: ПРИНЯТО
* **Контекст**:
  Интерфейс официального клиента собран на кастомных View 2013 года, что делает поддержку динамических тем Material You (Monet) и Predictive Back жестов крайне сложной и костыльной.
* **Решение**:
  Использовать современный декларативный Jetpack Compose со спецификацией **Material Design 3 Expressive**.
* **Последствия**:
  * Объем UI-кода сократился в 5–7 раз.
  * Плавность 120 FPS и адаптивные палитры под системные обои работают из коробки.

## [ADR-003] Локальное хранение истории сообщений и Anti-Delete в SQLite
* **Статус**: ПРИНЯТО
* **Контекст**:
  Для мгновенного старта приложения (<100мс) и работы режима Anti-Delete требуется независимое от сервера Telegram хранилище.
* **Решение**:
  Встроить легковесный SQLite через крейт `rusqlite` с флагом `bundled` прямо в Rust Core.
* **Последствия**:
  * Удаление сообщения собеседником на сервере не удаляет запись в БД, а переводит флаг `is_deleted = 1`.
  * Никаких внешних зависимостей от системного SQLite Android.

## [ADR-004] Встроенный автономный AI Агент через внутренний API
* **Статус**: ПРИНЯТО
* **Контекст**:
  Пользователь запросил интеллектуального ассистента, способного читать чаты, делать саммари, писать ответы и менять профиль.
* **Решение**:
  Реализовать агента через типизированный сервисный контракт `AgentExecutor`, исполняющий действия через внутренний API репозиториев ядра, а не через симуляцию кликов по экрану.
* **Последствия**:
  * Высокая скорость выполнения команд.
  * 100% надежность без зависимости от расположения кнопок на экране.
  * Возможность требовать явного подтверждения для внешних действий (отправка, удаление).
